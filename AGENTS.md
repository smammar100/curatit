# AGENTS.md — Curatit

**Design rules:** [.cursor/skills/curatit-design/SKILL.md](./.cursor/skills/curatit-design/SKILL.md) - read before creating or changing any UI.  

**Curatit** is a **directory / showcase-style marketing site** built with Next.js on a Lexington Themes template: homepage highlights featured “sites” (with Fuse.js search), a magazine-style **blog**, a **digital product store**, and supporting pages (pricing, advertise, submit, sign-in/up, system styleguide). It fits **SaaS/marketing, template marketplaces, and curated listings**. Original template publisher: [Lexington Themes](https://lexingtonthemes.com/).

## Tech stack

| Area | Details |
|------|---------|
| **Framework** | [Next.js](https://nextjs.org/) `^16` (App Router, React 19), all routes statically generated |
| **Styling** | [Tailwind CSS](https://tailwindcss.com/) `^4` via `@tailwindcss/postcss` (`postcss.config.mjs`) |
| **Markdown** | Frontmatter parsed with `yaml` and validated with `zod` in `src/lib/content.ts`; bodies rendered by `src/lib/markdown.ts` (unified: GFM, smartypants, heading ids, Shiki `min-light`) |
| **Search** | `fuse.js` in the client component `src/components/sites/SearchDialog.tsx` |
| **Tailwind plugins** | `@tailwindcss/forms`, `@tailwindcss/typography`, `tailwind-scrollbar-hide` (loaded with `@plugin` in `src/styles/global.css`) |
| **Fonts** | `next/font/google` (Inter, Hedvig Letters Serif) in `src/app/layout.tsx` |
| **Aliases** | `@/*` → `src/*` (`tsconfig.json`) |

## Content collections (`src/lib/content.ts`)

`getCollection(name)` returns entries sorted by filename (so `10.md` sorts before `2.md`); `getEntry(name, id)` finds one. IDs are the filename without `.md`/`.mdx`. Frontmatter is validated with zod at build time and a bad file fails the build with the file name. Image fields are paths under `public/` (e.g. `/images/blog/1.jpg`) and must exist.

## Routing conventions

| URL pattern | Source |
|-------------|--------|
| `/` | `src/app/(site)/page.tsx` — Curatit homepage built from `src/components/home/` (corridor hero, pinned problem → solution scroll section, how-it-works cards, category folders, MCP coming-soon, FAQ) |
| `/dashboard` | `src/app/dashboard/page.tsx` — the signed-in home (no site nav or footer, not indexed): the library as a feed after Cosmos, built from `src/components/dashboard/`. Design first: real posts, sample boards in memory, no login yet; `/signin` and `/signup` lead here until Supabase auth is wired |
| `/dashboard/p/[shortCode]` | `src/app/dashboard/p/[shortCode]/page.tsx` — a post's detail page (`PostView`), built for every published post at build time; one published later renders on its first visit |
| `/library` | `src/app/(site)/library/page.tsx` — real brand posts from `src/content/library/*.json` via `getLibrary()` in `src/lib/library.ts`, newest first |
| `/sites` | `src/app/(site)/sites/page.tsx` — website directory (the template's original homepage), renders `<Search />` |
| `/blog` | `src/app/(site)/blog/page.tsx` — lists `posts` |
| `/blog/posts/[slug]` | `src/app/(site)/blog/posts/[slug]/page.tsx` — `slug` = post `id` (e.g. `1` → `/blog/posts/1`) |
| `/blog/tags`, `/blog/tags/[tag]` | Tag index + filtered posts |
| `/store`, `/store/[slug]` | Store grid + product detail |
| `/sites/site/[slug]` | Site detail from `sites` (`SitesLayout`, renders `<Search />`) |
| `/sites/tags`, `/sites/tags/[tag]` | Tag index + filtered `sites` |
| `/legal/[slug]` | Legal pages |
| `/rss.xml` | `src/app/rss.xml/route.ts`, built from `posts` |
| `/sitemap.xml` | `src/app/sitemap.ts` — add new static routes to its list |
| `/system/*` | Styleguide (`overview`, `colors`, `typography`, `buttons`, `links`) |
| Other | `pricing`, `about`, `advertise`, `submit` in `(site)`; `signin`, `signup` in `(auth)` (no navigation or footer: one centred card over a drifting wall of library covers, see Guardrails); 404 is `src/app/not-found.tsx` |

Dynamic routes use `generateStaticParams` + `dynamicParams = false`, so unknown slugs 404.

## Customization

- **Site URL / domain:** `SITE_URL` in `src/lib/site.ts` (currently `https://yourdomain.com`). SEO placeholders (title, Open Graph, Twitter, canonical) live in `metadata` in `src/app/layout.tsx`.
- **Brand colors / typography:** `src/styles/global.css` — `@theme` (`--color-accent-*`, `--color-base-*`); font families are wired in `src/app/layout.tsx` and mapped to `--font-sans` / `--font-display`.
- **Navigation / footer:** `src/components/navigation/Navigation.tsx`, `MobileNav.tsx`, `src/components/global/Footer.tsx`.
- **Wordmark:** `src/components/assets/Logo.tsx` (outlined "Curatit" in Hedvig Letters Serif), the mark is `Symbol.tsx`, and `Lockup.tsx` sets the two side by side (the full logo, used in both navigations and the sign-in card); favicon is `src/app/icon.svg`.

## Guardrails

- Keep the folder name **`fundations`** as spelled in this repo (do not “fix” to *foundations* without a coordinated rename everywhere).
- Dark theme: `data-theme="dark"` on `<html>`, set before paint by `global/ThemeScript` (inline script: localStorage `theme`, else the system preference, and it keeps following the system while nothing is stored) and switched through `global/theme.ts` (`setThemeMode`: light, dark or system) by `global/ThemeToggle` (in `Navigation` and `MobileNav`; it also sets `data-theme-switching` for two frames so nothing tweens). Colours flip through the tokens: `:root[data-theme="dark"]` in `global.css` redefines `--color-white`, the `base` scale (reversed) and `accent` (less chroma), so components keep their light-mode classes and `dark:` (a custom variant on the attribute) is only for a different treatment, like the auth card's ring. `--color-paper` never flips (text on accent fills), `--color-edge` is the image/surface hairline (black/10, white/10 in dark), prose and Shiki (`min-light` / `min-dark`, both rendered) colours are mapped to the tokens in `global.css`, and inline colours in client components use `light-dark()`. `viewport.themeColor` in `layout.tsx` carries both canvases; update it if `--color-white` changes.
- Components are server components by default; client components (`"use client"`) are `MobileNav`, `SearchDialog`, `ThemeToggle`, the dashboard (`components/dashboard/*`), `ui/thought-line`, `SitesPreviewGrid`, the homepage demos (`SearchDemo`, `DetailDemo`, `BoardDemo`, `LibraryWindow`), `DemoParts` and `HomePosts`, the pinned problem/solution section (`ProblemSolution`, `Scattered`), the MCP demo (`McpDemo`), the CTA logo reels (`LogoReel`), (`Scattered` uses the `useIntroOnce` hook), `Categories`, plus `HydrateOnView`, `islands` and `MotionProvider` (framer-motion). `ui/image-stream-hero` is deliberately a server component (pure CSS keyframes); keep it that way. Keep content loading (`src/lib/content.ts`, which uses `node:fs`) out of client components.
- `src/components/ui/` holds components copied from shadcn / 21st.dev. They import `cn` from `@/lib/utils`; keep them close to upstream and style them from the outside. There is no `components.json`, so run `npx shadcn@latest init` before using the shadcn CLI (it also edits `global.css`, so review that diff).
- Icons in `src/components/fundations/icons/` are Phosphor (bold weight) paths on the shared `Icon` shell; take new ones from `@phosphor-icons/core` rather than adding an icon library (`npm pack @phosphor-icons/core` into a scratch folder and copy the path from `assets/bold/<name>-bold.svg`).
- `src/components/ui/thought-line.tsx` is React Bits' ThoughtLine (an agent's "thinking" line with a trace of steps), ported to TypeScript with framer-motion's `animate` and the site's Phosphor icons in place of its own dependencies; its stylesheet is imported from `global.css` so server-rendered markup is styled before the component's code arrives. The MCP demo (`McpDemo`) uses it for the agent's status line, with `live={false}` (the loop would spam a live region) and `elapsed` set to the scripted search time until the loop has run once. Always pass it real colours (`color`, `glyphColor`): its shimmer mixes the ink with transparent through `color-mix()`, which can't take the default `currentColor`, and the label would render invisible.
- Dashboard (`src/app/dashboard`, `src/components/dashboard/`), chosen from a three-way prototype on 2026-10-10 and modelled on Cosmos's signed-in home. `Feed` holds the header (mark, For you / Newest / Saved tabs with a count badge, a menu below `lg`; `SearchBox`; Create; Upgrade, which links to `/pricing`; `AccountMenu`) and the grid. The grid measures its own width before first paint and fits as many columns as the chosen tile size allows (target 460 / 320 / 230px; medium gives 3 columns at 1,166px and 5 at 1,860px, like Cosmos), with gaps from 24 to 40px; posts are dealt to the shortest column so the order reads across the top row. `SearchBox` is a pill that opens a panel over a dimmed page (Recent searches kept in localStorage `curatit-recent-searches`, the library's categories (`categories` in `home/demo.ts`) as swatch chips, Recently saved); `/` focuses it. `AccountMenu` holds profile, Saved posts, Contact us, Log out, and the Theme (light, dark, system, via `global/theme.ts`) and Grid size (localStorage `curatit-grid-size`) switches. `src/app/dashboard/layout.tsx` loads the posts and sample boards once and wraps every dashboard page in `PrefsProvider` (grid size) and `BoardsProvider` (`boards.tsx`: the boards in memory, `SaveMenu`, the toast and `notify()`, until they load from `public.boards` / `board_posts`), so both carry over between the feed and a post. `Header` and `Grid` are shared; every tile links to `/dashboard/p/<shortCode>`, and `?view=` / `?q=` open the feed on a view or search (`feedHref()` in `Feed`), which is how the detail page's tabs and search lead back. The post detail page (`PostView`, data from `getPostDetail()` in `src/lib/posts.ts`: every slide, the full caption, likes and comments) follows Cosmos's element page (Mobbin reference, 2026-10-10): one rounded card with the post large on the left and a 24rem panel on the right (brand and More menu with Copy link / Open on Instagram, the hook linking to Instagram, format, slides, date, counts, the caption with Show more, View on Instagram and the category, the boards it's on), a board picker and Save at the panel's foot, and "More in <category>" (same brand first) as a grid underneath. Carousels get Telescope's side arrows, a counter and a thumbnail strip, and ← / → step through slides; the image is sized so the card fits under the header (16rem of chrome for a single image, 22rem for a carousel). Search chips use the library's own category names (`Fintech`, not the homepage tab's `Finance`), since that's what the search matches. Cosmos's Following, Explore, Shop, Settings, Community and Switch account were left out: nothing in Curatit stands behind them yet. Rejected: "Workspace" (a sidebar app shell landing on board mosaics, after Pinterest, Air and Arcade; the most app-like, heavy chrome) and "Brief" (one "What are you briefing?" prompt with brief chips and matched-tag results, after v0 and Perplexity; browsing became second-class).
- Sign-in and sign-up (`src/app/(auth)`) share one layout: a centred card (mark and wordmark inline, heading `displaySM`, no ring, the site's one card shadow because it floats over imagery) over `components/auth/PostWall`, a six-column masonry of library covers whose columns drift and loop (`--animate-wall-*` in `global.css`, off under reduced motion) and dissolve at the top and bottom through an eased mask. Chosen from a three-way prototype on 2026-10-10 (after Pinterest's login): rejected "Wall" (a split layout with a tilted, drifting GridMotion wall after Mobbin's login; busiest, and hidden on phones) and "Editorial" (a split layout with one centred column of covers at mixed widths after Cosmos's login; calm but showed few posts). Form rules that came out of it: the card with its form must fit a 720px-tall viewport, so no "remember me" row and a single password field on sign-up; both forms are built from `components/auth/AuthParts` (`AuthField`, `OrDivider`).
- Library post images live in `public/images/library/` and are gitignored, so they exist only where they were downloaded; cards show a placeholder when a file is missing. The raw scrapes are in `data/instagram/` and `supabase/seed.sql` is built from them; both are gitignored (they include commenters' personal data and the repo is public), so they exist only where they were created.
- Supabase project `ytxtwowgxmztaboxgdmq`; env vars `NEXT_PUBLIC_SUPABASE_URL` and `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` in `.env.local` (gitignored). Apify items (`apify/instagram-post-scraper`, `dataDetailLevel: detailedData`) are split by `private.ingest_instagram_post(item)` into `instagram_posts` (a column per field plus the verbatim item in `raw`), `instagram_post_media` (carousel slides), `instagram_post_coauthors`, `instagram_tagged_users`, `instagram_comments` (editors only: written by the public) and `instagram_accounts`. Public reads go through RLS (published posts only), writes need `profiles.role` editor/admin. Change the schema with a new file in `supabase/migrations/`, never by editing an applied one.
- Database workflow (follows the `supabase` and `supabase-postgres-best-practices` skills): create a migration with `npx supabase migration new <name>` (`npx.cmd` in PowerShell), try the SQL first with `execute_sql` inside `begin; … rollback;`, apply with `npx supabase db push` (the MCP `apply_migration` call gets declined), then run the MCP `get_advisors` security and performance checks. New objects in `public` get no access by default (see `…_least_privilege_grants.sql`), so every migration that adds a table, view or function grants `anon` / `authenticated` exactly what they need and enables RLS with policies on any new table. Index every foreign key and every column a policy filters on, wrap `auth.uid()` as `(select auth.uid())` in policies, keep `security definer` functions in `private`, and use `security_invoker = true` on views. `get_shared_board()` is intentionally callable by `anon` (the advisor warns about it): the share token is the credential.
- Post images live in the public Storage bucket `library` as `<category>/<brand>/<format>/<short_code>/<nn>.webp` (category = the brand's industry, `brands.category_id`; format = `static` | `carousel` | `video`; `01.webp` is the cover, then one file per carousel slide in order; videos keep only their cover frame). `public.post_images` links each file to its post: one row per file keyed by `(post_id, position)`, where position 0 is the cover and carousel slide n is position n (same as `instagram_post_media.position`). A trigger rejects any path outside the post's own folder or at the wrong position, imports (`ingest_instagram_post`) never touch the table, and deleting a post removes its rows but not its files. Read paths from `post_images` (or `library_posts.cover_path`) rather than building them; the public URL is `supabase.storage.from("library").getPublicUrl(path)`. To add a brand: run `apify/instagram-post-scraper` on the profile (`resultsLimit: 30`, `skipPinnedPosts: true`, `dataDetailLevel: detailedData`), save its newest 5 non-reel posts with `node scripts/pick-library-posts.mjs <handle> <runId> <datasetId>`, and add the brand (category, slug, own accounts) to `scripts/library-sources.mjs`; then run `node scripts/download-library-images.mjs` (Instagram links expire within days; it keeps the original JPEGs in `data/storage/originals/` and writes WebP at quality 80, max 1080px wide, with `sharp` into `data/storage/library/`) and the upload commands it prints, then `node scripts/build-library-seed.mjs` and `npx supabase db query --linked -f supabase/seed.sql` (`db push --include-seed` only records the seed's hash once it has run). Since the 30-brand library (2026-10-10) the seed is over the query API's size limit (413), so split it at its `-- <Brand>: N posts from Apify run …` headers and run one chunk per brand; every statement is an upsert, so re-running any chunk is safe. Lessons from that run: Apify's free plan runs at most 5 actors at once; brands that post mostly reels (Expedia, Binance) need `resultsLimit: 80` to find 5 stills, and a brand with no stills at all can't join (Temu: 150 reels in a row, left out); upload one brand at a time with `storage cp -r data/storage/library/<category>/<brand> ss:///library/<category>`, but if that category folder doesn't exist in the bucket yet the CLI copies the folder's contents instead of the folder (Shopify's first upload landed in `ecommerce/carousel/…`, and a stray copy is still there), so check with `storage ls ss:///library/<category>/`. The food category is named "Food & drink" (slug and folder still `food-delivery`) since fast food and drinks joined it; Shopify and Amazon are "E-commerce" (`ecommerce`), the seventh homepage tab.
- Brand logos live in the same `library` bucket at `logos/<brand slug>.webp` (each brand's Instagram profile picture, 320px WebP at quality 90) and `brands.logo_path` points to them; a check constraint requires the path to match the brand's own slug, and `library_posts.brand_logo_path` exposes it. To refresh or add one: run `apify/instagram-profile-scraper` on the brands' main accounts (first entry of `brandAccounts`), save the fields to `data/instagram/profiles.json` as described at the top of `scripts/download-brand-logos.mjs`, run that script and the upload command it prints, then rebuild and run the seed. The migrations folder also holds two migrations another session applied straight to the database (`…_curatit_mcp_read_api`, `…_curatit_mcp_metric_provenance`), fetched with `npx supabase migration fetch --linked`; that command also rewrites existing files, so restore the others from git afterwards.
- The categories section (`Categories`) is a row of category tabs over one ten-slot gallery, chosen from a five-way prototype on 2026-10-10 (Mobbin refs: Instrument, Readymag). Each slot is a one-cell grid where the leaving and arriving covers overlap and cross-fade, so the grid never reflows; the selected pill slides with `layoutId`. Rejected: Index (serif list beside a gallery that follows hover), Tiles (category as a montage tile that opens a row beneath), Rails (one scrolling row per category), Deck (fanned hand of cards, one category at a time). Note: `AnimatePresence mode="popLayout"` is broken with framer-motion 14 + React 19 here (exiting items freeze at full opacity, entering ones at zero), so overlap old and new in a shared `[grid-area:1/1]` cell instead.
- Homepage performance (Lighthouse mobile median 92, desktop 100 on 2026-10-10; was 82 / 98). Mobile Lighthouse simulates a slow phone, and its LCP (the hero paragraph) counts every byte requested and every script run before that paint, so the rules are about keeping the hero's critical path small: (1) every section below the hero is wrapped in `HydrateOnView` in `page.tsx`, which keeps its server HTML untouched while hydrating and renders it for real only once it scrolls into view (or focus lands in it), and gives it `content-visibility: auto` so the browser neither lays it out nor fetches its lazy images until it is near (the collage just below the fold was otherwise loading during the hero's paint and swinging mobile LCP by half a second); (2) the client components inside those sections are imported from `src/components/home/islands.tsx`, never directly, so their code, and all of framer-motion with its `MotionProvider`, downloads only when a section comes alive. A new client component on the homepage below the hero gets an `island()` export there; one used by the hero or navigation stays a normal import. (3) The hero corridor is a server component and its covers request 256–640px files at quality 60. (4) Inter loads without its `opsz` axis (48 KB instead of 73 KB); Hedvig keeps it because the display sizes use it. `experimental.inlineCss` was tried and dropped: it doubled the HTML because Next also copies the CSS into the RSC payload. Measure with `next build && next start` plus `npx lighthouse@13.5.0 <url> --only-categories=performance`, never against `next dev`, and take the median of five runs (single runs swing ±10).
- The homepage shows real library posts from Supabase: `src/app/(site)/page.tsx` loads them with `getPublishedPosts()` (`src/lib/posts.ts`, at build time, revalidated hourly). Server sections (`HomeHero`, `Categories`, `ClosingCta`) take them as props; the client demos read the featured ones through `HomePostsProvider` / `usePosts()` (`src/components/home/HomePosts.tsx`). `src/components/home/demo.ts` picks which posts each section shows by Instagram short code and holds the editorial copy for them (briefs and matched tags, the detail view's analysis, board notes); that copy describes the real posts, so update it when you swap one. Post images render through `PostCover` (`next/image`, Supabase allowed in `next.config.ts`). The How it works illustrations (`SearchDemo`, `DetailDemo`, `BoardDemo`) use the "Filmstrip" direction, chosen from a prototype on 2026-10-10: results as a list with matched tags, the carousel as a strip of its slides with each one's role, the board as the client's read-only view with its share link. Rejected: "Window" (app-window chrome; read as screenshots of text) and "Collage" (fanned prints with floating UI; looked good but hid how the product works). Every illustration fills the same box (`HowItWorks` gives each an `absolute inset-x-6 top-0 -bottom-6` slot inside an `overflow-clip` card, so a click can't scroll the card) and sizes its images from the height left, so all three end on one line. Motion lives in `DemoParts.tsx`: `useIntro()` staggers the pieces in once when the card scrolls into view, `useLoop()` advances each demo while it is on screen and stops for good when the visitor clicks, `useTyped()` types the search query; all of it is off under reduced motion, and live regions are silent while a loop runs.
- Do not expand content schemas lightly; update all consumers (layouts, cards, `generateStaticParams`) in the same change.
- Prefer small diffs and existing patterns (`@/` imports, collection names `posts` | `sites` | `store` | `legal`).
