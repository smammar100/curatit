# AGENTS.md — Curatit

**Design rules:** [.cursor/skills/curatit-design/SKILL.md](./.cursor/skills/curatit-design/SKILL.md) - read before creating or changing any UI.  

**Curatit** is a **directory / showcase-style marketing site** built with Next.js on a Lexington Themes template: homepage highlights featured “sites” (with Fuse.js search), a magazine-style **blog**, a **digital product store**, and supporting pages (pricing, advertise, submit, sign-in/up, system styleguide). It fits **SaaS/marketing, template marketplaces, and curated listings**. Original template publisher: [Lexington Themes](https://lexingtonthemes.com/).

## Tech stack

| Area | Details |
|------|---------|
| **Framework** | [Next.js](https://nextjs.org/) `^16` (App Router, React 19), all routes statically generated |
| **Styling** | [Tailwind CSS](https://tailwindcss.com/) `^4` via `@tailwindcss/postcss` (`postcss.config.mjs`) |
| **Markdown** | Frontmatter parsed with `yaml` and validated with `zod` in `src/lib/content.ts`; bodies rendered by `src/lib/markdown.ts` (unified: GFM, smartypants, heading ids, Shiki `min-light`) |
| **Search** | `fuse.js` in the client component `src/components/sites/SearchDialog.tsx` |
| **Tailwind plugins** | `@tailwindcss/forms`, `@tailwindcss/typography`, `tailwind-scrollbar-hide` (loaded with `@plugin` in `src/styles/global.css`) |
| **Fonts** | `next/font/google` (Inter, Hedvig Letters Serif) in `src/app/layout.tsx` |
| **Aliases** | `@/*` → `src/*` (`tsconfig.json`) |

## Content collections (`src/lib/content.ts`)

`getCollection(name)` returns entries sorted by filename (so `10.md` sorts before `2.md`); `getEntry(name, id)` finds one. IDs are the filename without `.md`/`.mdx`. Frontmatter is validated with zod at build time and a bad file fails the build with the file name. Image fields are paths under `public/` (e.g. `/images/blog/1.jpg`) and must exist.

Rejected: "Cards" (a card per token saying in words what it can do, create and reveal in one native dialog; tallest with many tokens) and "Setup" (the token beside the client configuration it goes into, the secret written straight into the snippet; one motion, but it duplicated `/docs/mcp` and put the secret inside text that's easy to paste in the wrong place) |
| `/api/cron/creative-reconcile` | The daily reconcile (`vercel.json` crons, `Authorization: Bearer $CRON_SECRET`): queues posts due an analysis; never calls a model. Off unless `CREATIVE_ANALYSIS_ENABLED=true`, a dry run unless `CREATIVE_RECONCILE_APPLY=true` |

Dynamic routes use `generateStaticParams` + `dynamicParams = false`, so unknown slugs 404.

## Guardrails

- Page gutter and titles (2026-10-12, at the person's request): on phones everything sits 16px from the screen edges. The `Wrapper` is `px-4 sm:px-8` (32px from `sm` up, as before); the footer and Vision panels are inset `px-4` from the window; a narrow column inside a standard Wrapper is a plain `mx-auto max-w-xl sm:px-8` div, not a second Wrapper (that doubled the gutter on phones); sideways-scrolling rows bleed with `-mx-4 px-4`. Every marketing page's `h1` is one style, `Text tag="h1" variant="displayLG"` + `font-display font-light text-base-900` (30px on phones, 36px at `md`, 48px from `lg`): the homepage hero, Vision, Roadmap, 404, Submit, the share page and the template's pages included. The auth card's title (`displaySM`, inside a 448px card) and the dashboard's titles (the app's own `text-display` role) are card and app headings and keep their sizes. Checked by loading every route in same-origin iframes at 320, 375, 768, 1024 and 1280px and measuring sideways overflow, the gutter of every visible text element and every `h1`'s computed size; fixes that came out of it: the How it works cards (on phones an aspect ratio plus `min-h-110` forced a width wider than the screen, so phones get the height alone), the MCP section's grid (`grid-cols-1`, or its one implicit column grew to the chat demo's 512px), the dashboard header (`minmax(0,1fr)` for the search column, or the input's intrinsic width pushed the header 17px off a 320px screen) and the `/sites` search bar (`w-[calc(100%-2rem)]`).
- Keep the folder name **`fundations`** as spelled in this repo (do not “fix” to *foundations* without a coordinated rename everywhere).
- Dark theme: `data-theme="dark"` on `<html>`, set before paint by `global/ThemeScript` (inline script: localStorage `theme`, else the system preference, and it keeps following the system while nothing is stored) and switched through `global/theme.ts` (`setThemeMode`: light, dark or system) by `global/ThemeToggle` (in `Navigation` and `MobileNav`; it also sets `data-theme-switching` for two frames so nothing tweens). Colours flip through the tokens: `:root[data-theme="dark"]` in `global.css` redefines `--color-white`, the `base` scale (reversed) and `accent` (less chroma), so components keep their light-mode classes and `dark:` (a custom variant on the attribute) is only for a different treatment, like the auth card's ring. `--color-paper` never flips (text on accent fills), `--color-edge` is the image/surface hairline (black/10, white/10 in dark), prose and Shiki (`min-light` / `min-dark`, both rendered) colours are mapped to the tokens in `global.css`, and inline colours in client components use `light-dark()`. `viewport.themeColor` in `layout.tsx` carries both canvases; update it if `--color-white` changes.
- Type scale (dashboard): Fluid Functionalism's typography, installed 2026-10-10 with `npx shadcn@latest add https://www.fluidfunctionalism.com/r/typography.json --overwrite` (it wrote `src/lib/type-scale.ts` and `src/lib/size-context.tsx`, the `--fs-*` / `--lh-*` values on `:root`, the `text-<role>` theme tokens, and the `.typeset` prose styles; `--overwrite` replaced nothing, since neither file existed). Six roles, each a size and a leading, with a compact step: display 28/34 (24/30), title 16/22 (15/20), subtitle 14/20 (13/18), body 13/20 (12/18), caption 12/16 (11/14), micro 11/14 (10/12). The dashboard uses them as utilities (`text-display`, `text-title`, …; `cx` has no tailwind-merge, so the bare tokens are safe), and its base is the body role (a box-less `contents text-body` wrapper in `src/app/dashboard/layout.tsx`, so 13/20 is what anything without a role inherits). Display is set in the serif, light (`font-display text-display font-light`: board, post and new-board titles); every other role stays Inter. Mapping used: 28px titles to display, 17px to title, 15px to subtitle, 14px (`text-sm`) to body, 12px (`text-xs`) to caption, 11px to micro; primary buttons, menu items and empty-state titles to subtitle. Fields are body with `pointer-coarse:text-[16px]` (the scale's `fieldTouchClass`), so iOS doesn't zoom on focus. The marketing site, auth pages and share page keep their own `Text` sizes; the browser's 16px root is unchanged.
- Components are server components by default; client components (`"use client"`) are `MobileNav`, `SearchDialog`, `ThemeToggle`, the dashboard (`components/dashboard/*`), the auth forms (`auth/AuthForms`), `ui/thought-line`, `SitesPreviewGrid`, the homepage demos (`SearchDemo`, `DetailDemo`, `BoardDemo`, `LibraryWindow`), `DemoParts` and `HomePosts`, the pinned problem/solution section (`ProblemSolution`, `Scattered`), the MCP demo (`McpDemo`), the CTA logo reels (`LogoReel`), (`Scattered` uses the `useIntroOnce` hook), `Categories`, the Vision page's `vision/SelectionGraph` and `vision/Signature`, the vendored lifeline (`components/lifeline`, from `lifeline.tsx` down; the Roadmap page itself stays a server component), plus `HydrateOnView`, `islands` and `MotionProvider` (framer-motion). `ui/image-stream-hero` is deliberately a server component (pure CSS keyframes); keep it that way. Keep content loading (`src/lib/content.ts`, which uses `node:fs`) out of client components.
- `src/components/ui/` holds components copied from shadcn / 21st.dev. They import `cn` from `@/lib/utils`; keep them close to upstream and style them from the outside. `components.json` (written by hand on 2026-10-10, not by `shadcn init`, which would rewrite `global.css`) points the CLI at `src/styles/global.css` and the `@/` aliases; registry items still edit `global.css`, so review that diff.
- Icons in `src/components/fundations/icons/` are Phosphor (bold weight) paths on the shared `Icon` shell; take new ones from `@phosphor-icons/core` rather than adding an icon library (`npm pack @phosphor-icons/core` into a scratch folder and copy the path from `assets/bold/<name>-bold.svg`).
- `src/components/ui/thought-line.tsx` is React Bits' ThoughtLine (an agent's "thinking" line with a trace of steps), ported to TypeScript with framer-motion's `animate` and the site's Phosphor icons in place of its own dependencies; its stylesheet is imported from `global.css` so server-rendered markup is styled before the component's code arrives. The MCP demo (`McpDemo`) uses it for the agent's status line, with `live={false}` (the loop would spam a live region) and `elapsed` set to the scripted search time until the loop has run once. Always pass it real colours (`color`, `glyphColor`): its shimmer mixes the ink with transparent through `color-mix()`, which can't take the default `currentColor`, and the label would render invisible.
- Dashboard (`src/app/dashboard`, `src/components/dashboard/`), chosen from a three-way prototype on 2026-10-10 and modelled on Cosmos's signed-in home. `Feed` holds the header (mark, For you / Discover tabs (Newest was dropped on 2026-10-11: For you ranks on the person's answers and Discover browses by category, so a date-sorted view had no job left), a menu below `lg`; `SearchBox`; Create; Saved, a bookmark button with the count of saved posts that fills while you're on Saved or a board; `AccountMenu`) and the grid. Discover browses the library by category: `CategoryBar` above the grid, after Cosmos's Explore row (2026-10-11): All (Phosphor `SquaresFour`) and then each category as its icon (the homepage `Categories` tabs' icons, by slug: `dashboard/categoryIcons.ts`) and name in the tab size, quiet grey, only the categories that have posts (counting extra tags, see Categories below), with only the selected one in a pill: grey for All, a pale tint of the category's hue (`src/lib/categories.ts`) with the icon and name in a deep shade of it for a category (`light-dark()`, 6.3:1 or more in both themes). The row spreads evenly across the page (`justify-between`, 2026-10-13, at the person's request: the gaps grow, the tabs keep their size) and, once the tabs don't fit, scrolls sideways and fades the edge that has more beyond it, only while it does; picking one narrows the grid (search still applies), picking it again goes back to All, and `?view=discover&category=<slug>` opens it (`feedHref(view, query, category)`). The grid measures its own width before first paint and fits as many columns as the chosen tile size allows (target 460 / 320 / 230px; medium gives 3 columns at 1,166px and 5 at 1,860px, like Cosmos), with gaps from 24 to 40px; posts are dealt to the shortest column so the order reads across the top row. `SearchBox` is a pill ("Search brands, categories or ideas") that opens a panel over a dimmed page (Recent searches kept in localStorage `curatit-recent-searches`; Brands (2026-10-12): every brand with its mark, newest to the library first, narrowed as you type; the categories that have posts (`categoriesWithPosts()` in `src/lib/categories.ts`) as swatch chips; Recently saved); `/` focuses it. Matching lives in `dashboard/search.ts`: punctuation, accents and spacing are ignored ("hm" finds H&M, "coca cola" Coca-Cola, "ubereats" Uber Eats), and a query that is exactly a brand's name or slug (`brandNamed()`) shows that brand alone rather than every hook sharing the word. A floating bottom search bar after a reference video was built on 2026-10-10 and reverted the same day; the header pill stays. Since 2026-10-11 the pill wears a `BorderBeam` from `border-beam` (Libraries.dev, pinned at 1.4.1, no dependencies): `size="md"`, `colorVariant="colorful"`, `strength={0.7}`, a glow travelling round its edge, and the open panel under it wears one too (one `beam` settings object in `SearchBox`; the panel is placed by a plain div outside the beam, because the beam's own stylesheet sets `position: relative` on its wrapper and wins over Tailwind's `absolute`). It's the one place a full spectrum appears, a deliberate exception to the palette. Its `theme` follows the site's own switch through `useDarkTheme()` in `global/theme.ts` (the library's `auto` would follow the OS instead), `active` is off under reduced motion (its travelling types don't stop on their own), and `borderRadius` is passed (26 for the pill, 28 for the panel) because Tailwind's `rounded-full` computes to an effectively infinite radius the beam can't read. `AccountMenu` opens from the avatar itself (a 44px button with a ring on hover and while open; the separate chevron button was folded into it on 2026-10-11, in `LibraryWindow` too) and holds profile, Saved posts, Contact us, Log out, and the Theme (light, dark, system, via `global/theme.ts`) and Grid size (localStorage `curatit-grid-size`) switches. `src/app/dashboard/layout.tsx` loads the posts once (each with its `instagram_posts.id`, which `board_posts.post_id` refers to, besides the short code URLs use) and wraps every dashboard page in `UserProvider`, `ProfileProvider` (the onboarding answers), `PrefsProvider` (grid size) and `BoardsProvider`, so all of them carry over between the feed and a post. For you (2026-10-11) is the library ranked on the person's onboarding answers by `rank()` in `dashboard/forYou.ts`: an industry they picked counts 3, a brand they follow 2, and what the posts they tapped have in common 2 for the brand, 1 for the industry, 1 for the format, and (in the feed only, `{ fresh: true }`, since 2026-10-12) a post from the library's newest import day 3, so a new import is seen whatever the answers ("newest" read from the library's `addedAt`, not the clock); ties keep the feed's own order, and with no answers the order is unchanged. The feed's own order (`dashboard/layout.tsx`, 2026-10-12, after a new import was found scattered down the feed): newest import day first (`LibraryPost.addedAt` = `instagram_posts.created_at`), and within each day the brands interleaved, so an import leads without opening on one brand's run. The feed shows its skeleton until the profile has loaded, so it never shows one order and then another, and sends a profile with no `onboarded_at` to `/dashboard/welcome` (only from `/dashboard` itself: under a post opened from a link the post comes first; the skeleton stays up while that redirect is on its way). Mobile Lighthouse simulates a slow phone, and its LCP (the hero paragraph) counts every byte requested and every script run before that paint, so the rules are about keeping the hero's critical path small: (1) every section below the hero is wrapped in `HydrateOnView` in `page.tsx`, which keeps its server HTML untouched while hydrating and renders it for real only once it scrolls into view (or focus lands in it), and gives it `content-visibility: auto` so the browser neither lays it out nor fetches its lazy images until it is near (the collage just below the fold was otherwise loading during the hero's paint and swinging mobile LCP by half a second); its observer's root is 1px short at the bottom (`rootMargin: "0px 0px -1px 0px"`), because the first section starts exactly at the fold and would otherwise count as intersecting from load with a ratio of 0, never cross a threshold, and never come alive: that broke the pinned problem → solution scroll until 2026-10-10); (2) the client components inside those sections are imported from `src/components/home/islands.tsx`, never directly, so their code, and all of framer-motion with its `MotionProvider`, downloads only when a section comes alive. A new client component on the homepage below the hero gets an `island()` export there; one used by the hero or navigation stays a normal import. (3) The hero corridor is a server component and its covers request 256–640px files at quality 60. (4) Inter loads without its `opsz` axis (48 KB instead of 73 KB); Hedvig keeps it because the display sizes use it. `experimental.inlineCss` was tried and dropped: it doubled the HTML because Next also copies the CSS into the RSC payload. Measure with `next build && next start` plus `npx lighthouse@13.5.0 <url> --only-categories=performance`, never against `next dev`, and take the median of five runs (single runs swing ±10).
- The homepage shows real library posts from Supabase: `src/app/(site)/page.tsx` loads them with `getPublishedPosts()` (`src/lib/posts.ts`, at build time, revalidated hourly). Server sections (`HomeHero`, `Categories`, `ClosingCta`) take them as props; the client demos read the featured ones through `HomePostsProvider` / `usePosts()` (`src/components/home/HomePosts.tsx`). `src/components/home/demo.ts` picks which posts each section shows by Instagram short code and holds the editorial copy for them (briefs and matched tags, the detail view's analysis, board notes); that copy describes the real posts, so update it when you swap one. Post images render through `PostCover` (`next/image`, Supabase allowed in `next.config.ts`). `LibraryWindow`, the solution frame of the pinned problem → solution scroll, is the dashboard drawn small (2026-10-10, replacing an early sidebar concept): its header (mark, For you / Discover, the search pill holding the launch brief, Create, the Saved bookmark with its badge, the account), the feed as a masonry dealt row by row (three, four or five columns by the window's width), and one post being saved, with its hover state, the Save menu open on the board and the toast. Its posts are `libraryWindow` in `demo.ts`; keep it in step when the dashboard changes. The How it works illustrations (`SearchDemo`, `DetailDemo`, `BoardDemo`) use the "Filmstrip" direction, chosen from a prototype on 2026-10-10: results as a list with matched tags, the carousel as a strip of its slides with each one's role, the board as the client's read-only view with its share link. Rejected: "Window" (app-window chrome; read as screenshots of text) and "Collage" (fanned prints with floating UI; looked good but hid how the product works). Every illustration fills the same box (`HowItWorks` gives each an `absolute inset-x-6 top-0 -bottom-6` slot inside an `overflow-clip` card, so a click can't scroll the card) and sizes its images from the height left, so all three end on one line. Motion lives in `DemoParts.tsx`: `useIntro()` staggers the pieces in once when the card scrolls into view, `useLoop()` advances each demo while it is on screen and stops for good when the visitor clicks, `useTyped()` types the search query; all of it is off under reduced motion, and live regions are silent while a loop runs.
- Do not expand content schemas lightly; update all consumers (layouts, cards, `generateStaticParams`) in the same change.
