# AGENTS.md — Curatit

**Design rules:** [.cursor/skills/curatit-design/SKILL.md](./.cursor/skills/curatit-design/SKILL.md) - read before creating or changing any UI.  

**Curatit** is a **directory / showcase-style marketing site** built with Next.js on a Lexington Themes template: homepage highlights featured “sites” (with Fuse.js search), a magazine-style **blog**, a **digital product store**, and supporting pages (pricing, advertise, submit, sign-in/up, system styleguide). It fits **SaaS/marketing, template marketplaces, and curated listings**. Original template publisher: [Lexington Themes](https://lexingtonthemes.com/).

## Tech stack

| Area | Details |

| **Styling** | [Tailwind CSS](https://tailwindcss.com/) `^4` via `@tailwindcss/postcss` (`postcss.config.mjs`) |

## Content collections (`src/lib/content.ts`)

`getCollection(name)` returns entries sorted by filename (so `10.md` sorts before `2.md`); `getEntry(name, id)` finds one. IDs are the filename without `.md`/`.mdx`. Frontmatter is validated with zod at build time and a bad file fails the build with the file name. Image fields are paths under `public/` (e.g. `/images/blog/1.jpg`) and must exist.

## Routing conventions

| URL pattern | Source |
|-------------|--------|
| `/` | `src/app/(site)/page.tsx` — Curatit homepage built from `src/components/home/` (corridor hero, pinned problem → solution scroll section, how-it-works cards, category folders, MCP coming-soon, FAQ) |
| `/dashboard` | `src/app/dashboard/page.tsx` — the signed-in home (no site nav or footer, not indexed): the library as a feed after Cosmos, built from `src/components/dashboard/`. Real posts and the signed-in person's own boards (`public.boards` / `board_posts`, loaded in the browser); signed-out visitors are sent to `/signin?next=…` by the proxy |
| `/dashboard/b/[id]` | `src/app/dashboard/b/[id]/page.tsx` — a board's page (`BoardView`). Boards are per person and load in the browser, so it's one shell for every id, built on first visit and cached |
| `/s/[token]` | `src/app/s/[token]/page.tsx` — a board's read-only share link, public and not indexed, from `getSharedBoard()` in `src/lib/boards.ts`; rendered per request so a link that's turned off stops working at once |
| `/auth/callback` | `src/app/auth/callback/route.ts` — where the links in Supabase's emails (confirm sign-up, reset password) come back: exchanges the PKCE `?code=` (or verifies `?token_hash=&type=`) for a session and redirects to `?next=`, or to `/signin?error=<code>` |
| `/dashboard/p/[shortCode]` | A post, opened over the feed (`PostView`). Two slots fill it: the page (`src/app/dashboard/p/[shortCode]/page.tsx`, the feed underneath) and `@modal/p/[shortCode]` (the post). Opened from the feed, the intercepting route `@modal/(.)p/[shortCode]` shows it over the feed that's already there; `@modal/page.tsx` and `default.tsx` keep the slot empty otherwise. Built for every published post at build time (`postParams()` in `src/app/dashboard/post.tsx`); one published later renders on its first visit |
| `/library` | `src/app/(site)/library/page.tsx` — real brand posts from `src/content/library/*.json` via `getLibrary()` in `src/lib/library.ts`, newest first |
| `/sites` | `src/app/(site)/sites/page.tsx` — website directory (the template's original homepage), renders `<Search />` |
| `/blog` | `src/app/(site)/blog/page.tsx` — lists `posts` |
| `/blog/posts/[slug]` | `src/app/(site)/blog/posts/[slug]/page.tsx` — `slug` = post `id` (e.g. `1` → `/blog/posts/1`) |
| `/blog/tags`, `/blog/tags/[tag]` | Tag index + filtered posts |
| `/store`, `/store/[slug]` | Store grid + product detail |
| `/sites/site/[slug]` | Site detail from `sites` (`SitesLayout`, renders `<Search />`) |
| `/sites/tags`, `/sites/tags/[tag]` | Tag index + filtered `sites` |
| `/legal/[slug]` | Legal pages |
| `/rss.xml` | `src/app/rss.xml/route.ts`, built from `posts` |
| `/sitemap.xml` | `src/app/sitemap.ts` — add new static routes to its list |
| `/system/*` | Styleguide (`overview`, `colors`, `typography`, `buttons`, `links`) |
| Other | `pricing`, `about`, `advertise`, `submit` in `(site)`; `signin`, `signup`, `forgot-password`, `reset-password` in `(auth)` (no navigation or footer: one centred card over a drifting wall of library covers, see Guardrails); 404 is `src/app/not-found.tsx` |

Dynamic routes use `generateStaticParams` + `dynamicParams = false`, so unknown slugs 404.

## Guardrails

- Keep the folder name **`fundations`** as spelled in this repo (do not “fix” to *foundations* without a coordinated rename everywhere).
- Dark theme: `data-theme="dark"` on `<html>`, set before paint by `global/ThemeScript` (inline script: localStorage `theme`, else the system preference, and it keeps following the system while nothing is stored) and switched through `global/theme.ts` (`setThemeMode`: light, dark or system) by `global/ThemeToggle` (in `Navigation` and `MobileNav`; it also sets `data-theme-switching` for two frames so nothing tweens). Colours flip through the tokens: `:root[data-theme="dark"]` in `global.css` redefines `--color-white`, the `base` scale (reversed) and `accent` (less chroma), so components keep their light-mode classes and `dark:` (a custom variant on the attribute) is only for a different treatment, like the auth card's ring. `--color-paper` never flips (text on accent fills), `--color-edge` is the image/surface hairline (black/10, white/10 in dark), prose and Shiki (`min-light` / `min-dark`, both rendered) colours are mapped to the tokens in `global.css`, and inline colours in client components use `light-dark()`. `viewport.themeColor` in `layout.tsx` carries both canvases; update it if `--color-white` changes.
- Components are server components by default; client components (`"use client"`) are `MobileNav`, `SearchDialog`, `ThemeToggle`, the dashboard (`components/dashboard/*`), the auth forms (`auth/AuthForms`), `ui/thought-line`, `SitesPreviewGrid`, the homepage demos (`SearchDemo`, `DetailDemo`, `BoardDemo`, `LibraryWindow`), `DemoParts` and `HomePosts`, the pinned problem/solution section (`ProblemSolution`, `Scattered`), the MCP demo (`McpDemo`), the CTA logo reels (`LogoReel`), (`Scattered` uses the `useIntroOnce` hook), `Categories`, plus `HydrateOnView`, `islands` and `MotionProvider` (framer-motion). `ui/image-stream-hero` is deliberately a server component (pure CSS keyframes); keep it that way. Keep content loading (`src/lib/content.ts`, which uses `node:fs`) out of client components.
- `src/components/ui/` holds components copied from shadcn / 21st.dev. They import `cn` from `@/lib/utils`; keep them close to upstream and style them from the outside. There is no `components.json`, so run `npx shadcn@latest init` before using the shadcn CLI (it also edits `global.css`, so review that diff).
- Icons in `src/components/fundations/icons/` are Phosphor (bold weight) paths on the shared `Icon` shell; take new ones from `@phosphor-icons/core` rather than adding an icon library (`npm pack @phosphor-icons/core` into a scratch folder and copy the path from `assets/bold/<name>-bold.svg`).
- `src/components/ui/thought-line.tsx` is React Bits' ThoughtLine (an agent's "thinking" line with a trace of steps), ported to TypeScript with framer-motion's `animate` and the site's Phosphor icons in place of its own dependencies; its stylesheet is imported from `global.css` so server-rendered markup is styled before the component's code arrives. The MCP demo (`McpDemo`) uses it for the agent's status line, with `live={false}` (the loop would spam a live region) and `elapsed` set to the scripted search time until the loop has run once. Always pass it real colours (`color`, `glyphColor`): its shimmer mixes the ink with transparent through `color-mix()`, which can't take the default `currentColor`, and the label would render invisible.
- Dashboard (`src/app/dashboard`, `src/components/dashboard/`), chosen from a three-way prototype on 2026-10-10 and modelled on Cosmos's signed-in home. `Feed` holds the header (mark, For you / Newest / Saved tabs with a count badge, a menu below `lg`; `SearchBox`; Create; Upgrade, which links to `/pricing`; `AccountMenu`) and the grid. The grid measures its own width before first paint and fits as many columns as the chosen tile size allows (target 460 / 320 / 230px; medium gives 3 columns at 1,166px and 5 at 1,860px, like Cosmos), with gaps from 24 to 40px; posts are dealt to the shortest column so the order reads across the top row. `SearchBox` is a pill that opens a panel over a dimmed page (Recent searches kept in localStorage `curatit-recent-searches`, the library's categories (`categories` in `home/demo.ts`) as swatch chips, Recently saved); `/` focuses it. `AccountMenu` holds profile, Saved posts, Contact us, Log out, and the Theme (light, dark, system, via `global/theme.ts`) and Grid size (localStorage `curatit-grid-size`) switches. `src/app/dashboard/layout.tsx` loads the posts once (each with its `instagram_posts.id`, which `board_posts.post_id` refers to, besides the short code URLs use) and wraps every dashboard page in `UserProvider`, `PrefsProvider` (grid size) and `BoardsProvider`, so all three carry over between the feed and a post. Boards (`boards.tsx`, saved per user since 2026-10-10): `BoardsProvider` loads the signed-in person's boards with their posts from `public.boards` / `board_posts` in the browser once the page is up (the pages are static; Row Level Security returns only the owner's), drops posts that have since been unpublished, and lists boards by `updated_at`, which the `touch_board` trigger (`…_board_activity` migration) moves whenever a post is added or removed. Every change is optimistic: it shows at once with a toast, is written in the background, and is undone with an error toast if the write fails (a duplicate, `23505`, counts as saved). A new board gets its id in the browser (`crypto.randomUUID()`), so a post can be saved to it while it's still being written; writes to a board wait for its creation. Boards are always named (1 to 120 characters, a check on the table): Create in the header opens a name popover, the Save menu ends with "New board" (which saves the post to it) and a board with the post shows a check and takes it off again, and the post's picker has "New board…" (the only choice before the first board). The post's "Boards" section can take it off each board. While boards load, the Save menu, the picker and the Saved view say so instead of looking empty. The board page (`BoardView`, `/dashboard/b/<id>`, built 2026-10-10 after a Cosmos collection) is a centred header (a "Saved" link back, the name in the display serif, the description, the post count and when it was last used, Share and a More menu) over the board's posts in the feed's masonry, newest first, each with its note under it (`Grid`'s `footer`). The name, description and notes edit in place (Enter or leaving the field saves, Escape cancels; Shift+Enter for a new line in the description and notes); "Add a note" shows on hover, keyboard focus or always on touch, and keeps its space so tiles don't jump. Share makes a read-only link at `/s/<token>` (a new random token each time it's switched on, so turning it off and on kills old links; Copy, Open, Stop sharing). More has Rename, the description, and Delete, which asks first inside the menu with focus on Cancel, then goes to the Saved view. The Saved view opens on the boards as cards (`BoardList`: a mosaic of the newest three covers, name, count) above "All saved posts", and a post's Boards section links to each board. The Header shows Saved as the current tab on a board. A post opened from a board closes back to it (`backToPage()` in `Grid`, set by any tile not on a post's page), and `@modal/[...rest]` leaves the modal slot empty on any other dashboard page, so following a link out of an open post closes it. The share page (`/s/<token>`, a server page with no client code of its own) shows the Curatit lockup with "Make your own board", "Shared board · Read-only", the name, description and count, and the posts in CSS columns with their brand and note, each opening the post on Instagram. `get_shared_board()` lists posts by position, then newest first (`…_shared_board_newest_first`); the library view adds brand and size. Notes on a shared board are visible to anyone with the link, and the Share panel says so. `Header` and `Grid` are shared; every tile links to `/dashboard/p/<shortCode>`, and `?view=` / `?q=` open the feed on a view or search (`feedHref()` in `Feed`), which is how the detail page's tabs and search lead back. The header's middle column is `minmax(0,36rem)`, so between 1,024 and about 1,200px the search narrows instead of pushing the row wider than the window. The post detail (`PostView`, data from `getPostDetail()` in `src/lib/posts.ts`: every slide and which of them were videos on Instagram, the full caption, likes and comments, the posting account and whether it's verified, and how its likes compare with the brand's other library posts and the category's) is the "Closeup" direction, chosen from a five-way prototype on 2026-10-10 (after Pinterest's and Savee's closeups): the post opens over the feed it came from, never a page of its own. A dimmed, blurred feed behind; one rounded card with the post on a black stage on the left (counter, a "Video cover" badge on slides that were videos, side arrows, ← / → through slides) and a 27rem panel on the right: the brand as a 48px round logo with its name, verified seal, `@handle` and category, an Instagram link; the caption's first sentence as the title (whole, up to 160 characters) and the rest as its body (paragraphs, Instagram's spacer lines dropped, @mentions and #hashtags as links, Show more only when it's actually clipped); Performance (likes, comments, likes against the brand's average, the post's rank in its category by likes); the boards it's on; and the board picker with Save fixed at the foot. Arrows at the window's edges step through the feed's order with `replace` (so Back still closes the post), Close, Escape or a click on the dimmed feed close it. While it's open the page underneath (`#dashboard-page`, set in the layout) is `inert`, the root stops scrolling with its scrollbar's width padded back (otherwise the grid reflows and the feed jumps), focus moves into the post and returns to the tile after. Closing steps back in history when a tile opened the post over the feed (`backToFeed()` in `Grid`), so the feed is exactly where it was, and goes to `/dashboard` when the post was opened from a link. `Feed` only writes `?view` / `?q` to the address on `/dashboard` itself, or it would overwrite a post's address. Two sections were built and dropped on review: People (collaborators and tagged accounts, slide by slide) and Post (format, image or video mix, pixel size, time posted, location). Rejected directions: "Stage" (the post alone on a full-height backdrop, the details as an editorial block below it), "Strip" (every slide side by side in a sideways row, after the homepage's Filmstrip), "Study" (a magazine spread: a sticky column of words beside the slides stacked down the page) and "As posted" (the post framed as on Instagram, with Curatit's tools beside it). The previous detail page, a full page after Cosmos's element page with "More in <category>" underneath, was replaced by Closeup. Search chips use the library's own category names (`Fintech`, not the homepage tab's `Finance`), since that's what the search matches. Cosmos's Following, Explore, Shop, Settings, Community and Switch account were left out: nothing in Curatit stands behind them yet. Rejected: "Workspace" (a sidebar app shell landing on board mosaics, after Pinterest, Air and Arcade; the most app-like, heavy chrome) and "Brief" (one "What are you briefing?" prompt with brief chips and matched-tag results, after v0 and Perplexity; browsing became second-class).
- Sign-in and sign-up (`src/app/(auth)`) share one layout: a centred card (mark and wordmark inline, heading `displaySM`, no ring, the site's one card shadow because it floats over imagery) over `components/auth/PostWall`, a six-column masonry of library covers whose columns drift and loop (`--animate-wall-*` in `global.css`, off under reduced motion) and dissolve at the top and bottom through an eased mask. Chosen from a three-way prototype on 2026-10-10 (after Pinterest's login): rejected "Wall" (a split layout with a tilted, drifting GridMotion wall after Mobbin's login; busiest, and hidden on phones) and "Editorial" (a split layout with one centred column of covers at mixed widths after Cosmos's login; calm but showed few posts). Form rules that came out of it: the card with its form must fit a 720px-tall viewport, so no "remember me" row and a single password field on sign-up; both forms are built from `components/auth/AuthParts` (`AuthField`, `AuthNotice`).
- Auth (Supabase, wired 2026-10-10): email and password. Google sign-in was built and then taken out on 2026-10-10 until there's a Google Cloud OAuth client (to bring it back: a `signInWithOAuth` server action redirecting to `data.url` with `redirectTo` = `/auth/callback?next=…`, which already handles the code; check the provider is on in Auth's public `/auth/v1/settings` first, or a disabled one lands people on Supabase's raw JSON error). The forms live in `components/auth/AuthForms.tsx` (sign in, sign up, forgot password, reset password, each a client form on `useActionState`) and call the server actions in `src/app/auth/actions.ts`, which use the per-request client so the session cookies come back with the response; `src/lib/auth.ts` holds `safeNext()` (only same-site paths for `?next=`) and `authMessage()` (Supabase error codes in plain words). The auth pages stay static: `?next=` and `?error=` are read from the address in the browser. Sign-up shows "Check your email" (with Send again) while the project confirms addresses, and goes straight to the dashboard when it doesn't; an address that already has an account gets the same screen, so sign-up can't be used to find out who has one, and forgot password answers the same way for any address. Every emailed link returns through `/auth/callback?next=…`; with the default email templates that's a PKCE code, which only works in the browser that started the flow, so the copy says "open it in this browser". The proxy (`utils/supabase/middleware.ts`) is the gate: it refreshes the session with `getClaims()` (never `getSession()` on the server), sends signed-out visitors from `/dashboard/…` to `/signin?next=…`, sends signed-in ones from `/signin`, `/signup` and `/forgot-password` to `/dashboard`, and forwards a `?code=` that lands on `/` to the callback (Supabase falls back to the Site URL when a redirect isn't on its allow list). The dashboard's pages are static and hold nothing personal; `dashboard/user.tsx` (`UserProvider`, `useUser`, `Avatar`) reads who's signed in from the session in the browser, and goes to `/signin` on a sign-out in any tab; Log out in `AccountMenu` is the `signOut` action. New users get a `public.profiles` row from the `on_auth_user_created` trigger (`full_name`, `avatar_url` when a provider supplies them). Project settings this depends on (Supabase dashboard, Authentication): URL Configuration with the Site URL set to the production origin and `http://localhost:3000/**` plus the production `/**` in Redirect URLs; Allow anonymous sign-ins off (the gate treats any session as signed in); Minimum password length 8, to match the form; and either custom SMTP or "Confirm email" off, because Supabase's default sender only delivers to the project's team members, a few emails an hour (and since June 2026 Free projects on it can't edit the email templates, which is why the callback handles the default PKCE link).
- Library post images live in `public/images/library/` and are gitignored, so they exist only where they were downloaded; cards show a placeholder when a file is missing. The raw scrapes are in `data/instagram/` and `supabase/seed.sql` is built from them; both are gitignored (they include commenters' personal data and the repo is public), so they exist only where they were created.
- Supabase project `ytxtwowgxmztaboxgdmq`; env vars `NEXT_PUBLIC_SUPABASE_URL` and `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` in `.env.local` (gitignored). Apify items (`apify/instagram-post-scraper`, `dataDetailLevel: detailedData`) are split by `private.ingest_instagram_post(item)` into `instagram_posts` (a column per field plus the verbatim item in `raw`), `instagram_post_media` (carousel slides), `instagram_post_coauthors`, `instagram_tagged_users`, `instagram_comments` (editors only: written by the public) and `instagram_accounts`. Public reads go through RLS (published posts only), writes need `profiles.role` editor/admin. Change the schema with a new file in `supabase/migrations/`, never by editing an applied one.
- Database workflow (follows the `supabase` and `supabase-postgres-best-practices` skills): create a migration with `npx supabase migration new <name>` (`npx.cmd` in PowerShell), try the SQL first with `execute_sql` inside `begin; … rollback;`, apply with `npx supabase db push` (the MCP `apply_migration` call gets declined), then run the MCP `get_advisors` security and performance checks. New objects in `public` get no access by default (see `…_least_privilege_grants.sql`), so every migration that adds a table, view or function grants `anon` / `authenticated` exactly what they need and enables RLS with policies on any new table. Index every foreign key and every column a policy filters on, wrap `auth.uid()` as `(select auth.uid())` in policies, keep `security definer` functions in `private`, and use `security_invoker = true` on views. `get_shared_board()` is intentionally callable by `anon` (the advisor warns about it): the share token is the credential.
- Post images live in the public Storage bucket `library` as `<category>/<brand>/<format>/<short_code>/<nn>.webp` (category = the brand's industry, `brands.category_id`; format = `static` | `carousel` | `video`; `01.webp` is the cover, then one file per carousel slide in order; videos keep only their cover frame). `public.post_images` links each file to its post: one row per file keyed by `(post_id, position)`, where position 0 is the cover and carousel slide n is position n (same as `instagram_post_media.position`). A trigger rejects any path outside the post's own folder or at the wrong position, imports (`ingest_instagram_post`) never touch the table, and deleting a post removes its rows but not its files. Read paths from `post_images` (or `library_posts.cover_path`) rather than building them; the public URL is `supabase.storage.from("library").getPublicUrl(path)`. To add a brand: run `apify/instagram-post-scraper` on the profile (`resultsLimit: 30`, `skipPinnedPosts: true`, `dataDetailLevel: detailedData`), save its newest 5 non-reel posts with `node scripts/pick-library-posts.mjs <handle> <runId> <datasetId>`, and add the brand (category, slug, own accounts) to `scripts/library-sources.mjs`; then run `node scripts/download-library-images.mjs` (Instagram links expire within days; it keeps the original JPEGs in `data/storage/originals/` and writes WebP at quality 80, max 1080px wide, with `sharp` into `data/storage/library/`) and the upload commands it prints, then `node scripts/build-library-seed.mjs` and `npx supabase db query --linked -f supabase/seed.sql` (`db push --include-seed` only records the seed's hash once it has run). Since the 30-brand library (2026-10-10) the seed is over the query API's size limit (413), so split it at its `-- <Brand>: N posts from Apify run …` headers and run one chunk per brand; every statement is an upsert, so re-running any chunk is safe. Lessons from that run: Apify's free plan runs at most 5 actors at once; brands that post mostly reels (Expedia, Binance) need `resultsLimit: 80` to find 5 stills, and a brand with no stills at all can't join (Temu: 150 reels in a row, left out); upload one brand at a time with `storage cp -r data/storage/library/<category>/<brand> ss:///library/<category>`, but if that category folder doesn't exist in the bucket yet the CLI copies the folder's contents instead of the folder (Shopify's first upload landed in `ecommerce/carousel/…`, and a stray copy is still there), so check with `storage ls ss:///library/<category>/`. Amazon's first upload also stopped partway (9 of its 15 files, three covers among them, re-uploaded on 2026-10-10), so after any upload check that every `post_images.path` of a published post has a row in `storage.objects` (bucket `library`): a missing file shows up as a 400 from `/_next/image`. The food category is named "Food & drink" (slug and folder still `food-delivery`) since fast food and drinks joined it; Shopify and Amazon are "E-commerce" (`ecommerce`), the seventh homepage tab.
- Brand logos live in the same `library` bucket at `logos/<brand slug>.webp` (each brand's Instagram profile picture, 320px WebP at quality 90) and `brands.logo_path` points to them; a check constraint requires the path to match the brand's own slug, and `library_posts.brand_logo_path` exposes it. To refresh or add one: run `apify/instagram-profile-scraper` on the brands' main accounts (first entry of `brandAccounts`), save the fields to `data/instagram/profiles.json` as described at the top of `scripts/download-brand-logos.mjs`, run that script and the upload command it prints, then rebuild and run the seed. The migrations folder also holds two migrations another session applied straight to the database (`…_curatit_mcp_read_api`, `…_curatit_mcp_metric_provenance`), fetched with `npx supabase migration fetch --linked`; that command also rewrites existing files, so restore the others from git afterwards.
- The categories section (`Categories`) is a row of category tabs over one ten-slot gallery, chosen from a five-way prototype on 2026-10-10 (Mobbin refs: Instrument, Readymag). Each slot is a one-cell grid where the leaving and arriving covers overlap and cross-fade, so the grid never reflows; the selected pill slides with `layoutId`. Rejected: Index (serif list beside a gallery that follows hover), Tiles (category as a montage tile that opens a row beneath), Rails (one scrolling row per category), Deck (fanned hand of cards, one category at a time). Note: `AnimatePresence mode="popLayout"` is broken with framer-motion 14 + React 19 here (exiting items freeze at full opacity, entering ones at zero), so overlap old and new in a shared `[grid-area:1/1]` cell instead.
- Homepage performance (Lighthouse mobile median 92, desktop 100 on 2026-10-10; was 82 / 98). Mobile Lighthouse simulates a slow phone, and its LCP (the hero paragraph) counts every byte requested and every script run before that paint, so the rules are about keeping the hero's critical path small: (1) every section below the hero is wrapped in `HydrateOnView` in `page.tsx`, which keeps its server HTML untouched while hydrating and renders it for real only once it scrolls into view (or focus lands in it), and gives it `content-visibility: auto` so the browser neither lays it out nor fetches its lazy images until it is near (the collage just below the fold was otherwise loading during the hero's paint and swinging mobile LCP by half a second); (2) the client components inside those sections are imported from `src/components/home/islands.tsx`, never directly, so their code, and all of framer-motion with its `MotionProvider`, downloads only when a section comes alive. A new client component on the homepage below the hero gets an `island()` export there; one used by the hero or navigation stays a normal import. (3) The hero corridor is a server component and its covers request 256–640px files at quality 60. (4) Inter loads without its `opsz` axis (48 KB instead of 73 KB); Hedvig keeps it because the display sizes use it. `experimental.inlineCss` was tried and dropped: it doubled the HTML because Next also copies the CSS into the RSC payload. Measure with `next build && next start` plus `npx lighthouse@13.5.0 <url> --only-categories=performance`, never against `next dev`, and take the median of five runs (single runs swing ±10).
- The homepage shows real library posts from Supabase: `src/app/(site)/page.tsx` loads them with `getPublishedPosts()` (`src/lib/posts.ts`, at build time, revalidated hourly). Server sections (`HomeHero`, `Categories`, `ClosingCta`) take them as props; the client demos read the featured ones through `HomePostsProvider` / `usePosts()` (`src/components/home/HomePosts.tsx`). `src/components/home/demo.ts` picks which posts each section shows by Instagram short code and holds the editorial copy for them (briefs and matched tags, the detail view's analysis, board notes); that copy describes the real posts, so update it when you swap one. Post images render through `PostCover` (`next/image`, Supabase allowed in `next.config.ts`). The How it works illustrations (`SearchDemo`, `DetailDemo`, `BoardDemo`) use the "Filmstrip" direction, chosen from a prototype on 2026-10-10: results as a list with matched tags, the carousel as a strip of its slides with each one's role, the board as the client's read-only view with its share link. Rejected: "Window" (app-window chrome; read as screenshots of text) and "Collage" (fanned prints with floating UI; looked good but hid how the product works). Every illustration fills the same box (`HowItWorks` gives each an `absolute inset-x-6 top-0 -bottom-6` slot inside an `overflow-clip` card, so a click can't scroll the card) and sizes its images from the height left, so all three end on one line. Motion lives in `DemoParts.tsx`: `useIntro()` staggers the pieces in once when the card scrolls into view, `useLoop()` advances each demo while it is on screen and stops for good when the visitor clicks, `useTyped()` types the search query; all of it is off under reduced motion, and live regions are silent while a loop runs.
- Do not expand content schemas lightly; update all consumers (layouts, cards, `generateStaticParams`) in the same change.
- Prefer small diffs and existing patterns (`@/` imports, collection names `posts` | `sites` | `store` | `legal`).
